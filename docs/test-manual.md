# 校园活动报名系统测试手册

本手册供小组成员在 Windows PowerShell 中验收当前四模块桌面程序。按顺序执行主流程，可同时检查学生、活动、报名和查询之间的数据联动。系统使用进程内内存保存数据，关闭程序即清空；每次完整复测都应重新启动程序。

## 1. 测试范围与通过标准

| 模块 | 重点检查 |
| --- | --- |
| 学生管理 | 新增、重复学号拦截、修改姓名与年级、列表刷新 |
| 活动管理 | 创建、时间和容量校验、修改名称、关闭报名 |
| 报名与取消 | 正式报名、满额候补、重复报名拦截、取消后递补 |
| 查询统计 | 个人历史、活动名单和状态筛选、活动统计、按日期总览 |

主流程用例全部符合预期、异常输入不会产生错误数据，且自动化测试无失败时，本轮验收通过。核心业务测试覆盖率应不低于 80%。如果 Tk 界面用例因环境缺少 Tcl/Tk 而跳过，仍须在可启动界面的电脑上完成本手册的手工步骤。

## 2. 环境准备

1. 安装 Python 3.12，在仓库根目录打开 PowerShell。
2. 首次运行时创建虚拟环境并安装锁定依赖；已有 `.venv` 时可跳过创建步骤。

   ```powershell
   python -m venv .venv
   .venv\Scripts\python -m pip install -r requirements-dev.txt
   ```

3. 启动程序，确认窗口含“学生管理”“活动管理”“报名与取消”“查询统计”四个页签。

   ```powershell
   .venv\Scripts\python -m campusApp.app
   ```

4. 在“学生管理”和“活动管理”点击“刷新列表”，确认新进程内没有旧数据。若已有测试数据，关闭程序后重新启动，再从用例 `STU-01` 开始。

### 测试数据

| 代号 | 输入 |
| --- | --- |
| 学生甲 | 学号 `0000000001`、姓名 `张三`、年级 `2` |
| 学生乙 | 学号 `0000000002`、姓名 `李四`、年级 `3` |
| 活动 A | 名称 `校园读书会`、容量 `1`、时长 `60` 分钟 |
| 活动 B | 名称 `校园摄影课`、容量 `1`、时长 `60` 分钟 |

活动 A、B 使用同一组相对当前时间生成的北京时间。运行以下命令，按输出填写三个时间字段；若测试已经耗时超过 30 分钟，请重新生成时间并重启本轮测试。

```powershell
@'
from datetime import datetime, timedelta, timezone

now = datetime.now(timezone(timedelta(hours=8)))
for label, minutes in (("报名开始", -10), ("报名截止", 30), ("活动开始", 60)):
  value = (now + timedelta(minutes=minutes)).strftime("%Y-%m-%d %H:%M:%S")
  print(f"{label}: {value}")
'@ | .venv\Scripts\python -
```

记录输出中的“活动开始”日期，供 `QRY-03` 填写总览开始日期。三个时间必须满足“报名开始 < 报名截止 ≤ 活动开始”，活动开始须晚于当前北京时间。

## 3. 四模块主流程

以下用例使用第 2 节的测试数据。在每个输入框中先清除旧值再填写新值；下拉框中的学生通常显示为“学号 姓名”，活动显示为“活动名称（容量 1）”。若选项未出现，先点击该页“刷新”。每次弹窗后先关闭弹窗，再检查列表或统计结果。执行 `ACT-03` 后先完成第 4 节中需要旧数据的异常用例，再执行 `RESET-01`。

### STU-01：新增两名学生

- **输入参数：**学生甲：学号 `0000000001`、姓名 `张三`、年级 `2`；学生乙：学号 `0000000002`、姓名 `李四`、年级 `3`。
- **操作步骤：**打开“学生管理”，在“新增学生”区域填入学生甲三个字段，点击“新增学生”；把三个字段改为学生乙的数据，再点一次“新增学生”；最后点击“刷新列表”。
- **预期结果：**两次均提示“学生创建成功”；列表恰有两行，编号分别为 `1`、`2`，学号前导零未丢失，姓名与年级和输入一致。

### STU-02：重复学号被拒绝

- **输入参数：**学号 `0000000001`、姓名 `赵六`、年级 `1`。
- **操作步骤：**仍在“学生管理”的新增区域输入上述三个值，点击“新增学生”，关闭错误弹窗后点击“刷新列表”。
- **预期结果：**提示“学号已存在”；列表仍只有学生甲和学生乙，没有新增“赵六”。

### ACT-01：创建可报名的活动 A

- **输入参数：**活动名称 `校园读书会`、活动容量 `1`、时长（分钟）`60`；“报名开始”“报名截止”“活动开始”依次填入第 2 节命令生成的三个完整时间。
- **操作步骤：**打开“活动管理”，逐一填写六个输入框，点击“创建活动”，再点击“刷新列表”。
- **预期结果：**提示“活动创建成功”；列表出现编号 `1`、名称 `校园读书会`、容量 `1`、时长 `60` 的活动；“阶段”为“报名中”，“活动结束”比“活动开始”晚 60 分钟。

### REG-01：正式报名与满额候补

- **输入参数：**第一次选学生 `0000000001 张三`、活动 `校园读书会（容量 1）`；第二次改选学生 `0000000002 李四`，活动保持不变。
- **操作步骤：**打开“报名与取消”，必要时点击“报名申请”区的“刷新”；按第一次参数选择两个下拉框，点击“提交报名”；关闭成功弹窗后改选学生乙，再点击“提交报名”；分别切换学生甲、乙查看“报名历史”。
- **预期结果：**第一次提示“正式报名，剩余名额 0”，甲的历史有一条正式报名；第二次提示“候补，剩余名额 0”，乙的历史有一条候补。两条记录对应同一个活动，编号各不相同。

### REG-02：重复报名被拒绝

- **输入参数：**学生 `0000000002 李四`、活动 `校园读书会（容量 1）`。
- **操作步骤：**在“报名与取消”的两个下拉框选择上述值，再点击“提交报名”；关闭错误弹窗后点击“刷新历史”。
- **预期结果：**出现重复报名的中文错误，状态行显示“报名失败”；学生乙的历史仍只有 `REG-01` 创建的一条候补记录。

### QRY-01：取消前的活动名单与统计

- **输入参数：**“活动报名名单”选择活动 `1 - 校园读书会`、状态“全部”、页码 `1`、每页 `10`；“活动统计”选择同一活动。
- **操作步骤：**打开“查询统计”，点击顶部“刷新”；进入“活动报名名单”，填写或选择上述参数后点击“查询”；进入“活动统计”，选择活动 A 并点击“查询统计”。
- **预期结果：**名单显示“共 2 条”，甲的状态为“正式报名”、乙为“候补”；统计显示容量 `1`、正式报名 `1`、候补 `1`、已取消 `0`、剩余名额 `0`、占用率 `100.00%`。

### REG-03：取消正式报名并自动递补

- **输入参数：**学生 `0000000001 张三`；在其历史中选中活动 A 的正式报名记录。
- **操作步骤：**回到“报名与取消”，选择学生甲，在“报名历史”中单击该记录，点击“取消选中报名”；关闭成功弹窗后点击“刷新历史”；再改选学生乙，点击“刷新历史”。
- **预期结果：**弹窗包含“已取消”和“已递补为正式报名”；甲的原记录仍在，状态改为“已取消”且有取消时间；乙的原候补记录变为“正式报名”，未新增第三条报名。

### QRY-02：取消后的个人记录、筛选与统计

- **输入参数：**“个人报名记录”分别选择 `0000000001 - 张三`、`0000000002 - 李四`，页码 `1`、每页 `10`；“活动报名名单”选活动 A，依次选择状态“全部”“正式报名”“候补”“已取消”，页码 `1`、每页 `10`。
- **操作步骤：**打开“查询统计”并点击顶部“刷新”；按参数分别查询甲、乙的个人记录；进入“活动报名名单”，每换一次状态都点击“查询”；最后进入“活动统计”，选择活动 A 并点击“查询统计”。
- **预期结果：**甲的个人记录为“已取消”，乙为“正式报名”；活动名单在四种筛选下分别为 `2`、`1`、`0`、`1` 条，候补筛选显示无符合条件的记录；统计为正式报名 `1`、候补 `0`、已取消 `1`、剩余名额 `0`、占用率 `100.00%`。

### QRY-03：按活动开始日期查看总览

- **输入参数：**“开始日期”填活动 A 的“活动开始”日期部分，格式 `YYYY-MM-DD`；“天数”填 `1`。例如活动开始为 `2026-10-21 15:00:00` 时，填 `2026-10-21`。实际操作应使用第 2 节生成的日期。
- **操作步骤：**在创建活动 B 之前，进入“查询统计”→“总览统计”，清除默认开始日期并填入上述日期，把天数改为 `1`，点击“统计”。
- **预期结果：**显示活动数量 `1`、正式报名 `1`、候补 `0`、已取消 `1`、去重参与学生数 `1`。

### STU-03：修改学生资料并检查关联查询

- **输入参数：**在学生列表选中编号 `2`；修改区域姓名填 `王五`、年级保留 `3`。
- **操作步骤：**回到“学生管理”，单击学生乙所在行，确认上方“修改选中学生”区域已带出原姓名与年级；按参数修改并点击“保存姓名与年级”；进入“查询统计”点击顶部“刷新”，在“活动报名名单”选择活动 A、状态“全部”、页码 `1`、每页 `10` 后点击“查询”。
- **预期结果：**提示“学生资料已更新”；学生列表中编号 `2` 的姓名为“王五”、学号仍为 `0000000002`、年级仍为 `3`；活动名单对应行显示“王五”，其正式报名状态不变。

### ACT-02：修改活动名称并检查关联记录

- **输入参数：**选中编号 `1` 的活动；“选中活动后修改名称”输入 `校园阅读会`。
- **操作步骤：**打开“活动管理”，单击活动 A 所在行，填写新名称并点击“修改名称”；在“查询统计”点击顶部“刷新”，进入“个人报名记录”，选择学生乙 `0000000002 - 王五`、页码 `1`、每页 `10`，点击“查询”。
- **预期结果：**提示“活动名称已更新”；活动列表显示“校园阅读会”；学生乙的个人记录中活动名称同步为“校园阅读会”，状态仍为“正式报名”。

### ACT-03：关闭活动 B 报名

- **输入参数：**新活动名称 `校园摄影课`、容量 `1`、时长 `60`，三个时间仍使用第 2 节生成的值；报名尝试选学生 `0000000001 张三`、活动 `校园摄影课（容量 1）`。
- **操作步骤：**在“活动管理”用上述六项参数创建活动 B；单击活动 B 所在行并点击“关闭报名”；再到“报名与取消”点击“刷新”，选择学生甲和活动 B 后点击“提交报名”。
- **预期结果：**创建后活动 B 编号为 `2`；关闭时提示“活动报名已关闭”，列表“阶段”为“报名关闭”；报名被拒绝且学生甲历史中没有活动 B 记录，活动 A 的历史不变。

### RESET-01：关闭程序后内存数据清空

- **输入参数：**重启后再次新增学生甲：学号 `0000000001`、姓名 `张三`、年级 `2`。
- **操作步骤：**关闭整个应用窗口，重新运行第 2 节的启动命令；查看“学生管理”和“活动管理”列表，进入“报名与取消”检查下拉框与历史；先执行第 4 节的 `STU-E03`、`REG-E01`，然后按上述参数重新新增学生甲。
- **预期结果：**重启时旧学生、旧活动和旧报名均不存在；两个空选择用例均给出提示；重新新增学生甲成功，编号重新从 `1` 开始。`RESET-01` 会清空本轮数据，应放在所有依赖旧数据的用例之后。

**操作提醒：**报名页的“报名历史”跟随当前选中的学生；查询页“刷新”只更新下拉选项，已经显示的查询结果需要再次点击“查询”或“查询统计”才能更新。

## 4. 异常与边界检查

除 `STU-E03`、`REG-E01` 外，在 `ACT-03` 后、`RESET-01` 前执行。本节各行中的异常值要**分别测试，每次只改一个字段**；未说明的字段沿用第 2 节的有效数据与时间。每次点击按钮后，确认出现中文错误、记录数没有增加，再恢复有效值测试下一项。`STU-E03` 和 `REG-E01` 按 `RESET-01` 的步骤，在刚重启、尚未新增新学生时执行。

| `REG-E01` | 学生、活动下拉框保持未选择；历史表格不选记录。 | 刚重启后进入“报名与取消”，先点“提交报名”，再点“取消选中报名”。 | 均提示先选择学生；没有生成报名或取消记录。 |
| `QRY-E01` | 活动选“校园阅读会”、状态“全部”；页码依次单独填 `0`、`10001`，每页依次单独填 `0`、`101`，另一个数字字段保持 `1` 或 `10`。 | 在“查询统计”→“活动报名名单”每改一个参数就点击“查询”。 | 每次都显示中文校验错误；页码允许 1～10000，每页允许 1～100；原报名记录不变。 |
