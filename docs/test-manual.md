# 校园活动报名系统测试手册

本手册供小组成员在 Windows PowerShell 中验收当前四模块桌面程序。按顺序执行主流程，可同时检查学生、活动、报名和查询之间的数据联动。系统使用进程内内存保存数据，关闭程序即清空；每次完整复测都应重新启动程序。

## 1. 测试范围与通过标准

| 模块 | 重点检查 |
| --- | --- |
| 学生管理 | 新增、重复学号拦截、修改姓名与年级、列表刷新 |
| 活动管理 | 创建、时间和容量校验、修改名称、关闭报名 |
| 报名与取消 | 正式报名、满额候补、重复报名拦截、取消后递补 |
| 查询统计 | 个人历史、活动名单和状态筛选、活动统计、按日期总览 |

主流程用例全部符合预期、异常输入不会产生错误数据，且自动化测试无失败时，本轮验收通过。核心业务测试覆盖率应不低于 80%。如果 Tk 界面用例因环境缺少 Tcl/Tk 而跳过，仍须在可启动界面的电脑上完成本手册的手工步骤。

## 2. 环境准备

1. 安装 Python 3.12，在仓库根目录打开 PowerShell。
2. 首次运行时创建虚拟环境并安装锁定依赖；已有 `.venv` 时可跳过创建步骤。

   ```powershell
   python -m venv .venv
   .venv\Scripts\python -m pip install -r requirements-dev.txt
   ```

3. 启动程序，确认窗口含“学生管理”“活动管理”“报名与取消”“查询统计”四个页签。

   ```powershell
   .venv\Scripts\python -m campusApp.app
   ```

4. 在“学生管理”和“活动管理”点击“刷新列表”，确认新进程内没有旧数据。若已有测试数据，关闭程序后重新启动，再从用例 `STU-01` 开始。

### 测试数据

| 代号 | 输入 |
| --- | --- |
| 学生甲 | 学号 `0000000001`、姓名 `张三`、年级 `2` |
| 学生乙 | 学号 `0000000002`、姓名 `李四`、年级 `3` |
| 活动 A | 名称 `校园读书会`、容量 `1`、时长 `60` 分钟 |
| 活动 B | 名称 `校园摄影课`、容量 `1`、时长 `60` 分钟 |

活动 A、B 使用同一组相对当前时间生成的北京时间。运行以下命令，按输出填写三个时间字段；若测试已经耗时超过 30 分钟，请重新生成时间并重启本轮测试。

```powershell
@'
from datetime import datetime, timedelta, timezone

now = datetime.now(timezone(timedelta(hours=8)))
for label, minutes in (("报名开始", -10), ("报名截止", 30), ("活动开始", 60)):
  value = (now + timedelta(minutes=minutes)).strftime("%Y-%m-%d %H:%M:%S")
  print(f"{label}: {value}")
'@ | .venv\Scripts\python -
```

记录输出中的“活动开始”日期，供 `QRY-03` 填写总览开始日期。三个时间必须满足“报名开始 < 报名截止 ≤ 活动开始”，活动开始须晚于当前北京时间。

## 3. 四模块主流程

按表中顺序操作；每步都记录实际结果。弹出“操作成功”后关闭提示框，再继续下一步。

| 编号 | 操作步骤 | 预期结果 |
| --- | --- | --- |
| `STU-01` | 在“学生管理”依次输入学生甲、乙的数据，各点击一次“新增学生”。 | 列表出现两条记录；学号前导零保留，学生编号分别为 1、2。 |
| `STU-02` | 再次输入学生甲的学号，点击“新增学生”。 | 显示中文重复学号错误；列表仍只有两条学生记录。 |
| `ACT-01` | 在“活动管理”填写活动 A 及生成的三个时间，点击“创建活动”。 | 列表出现容量 1 的活动 A；阶段为“报名中”，结束时间比活动开始晚 60 分钟。 |
| `REG-01` | 在“报名与取消”依次选择学生甲和活动 A、学生乙和活动 A，各点击“提交报名”。 | 学生甲为“正式报名”，学生乙为“候补”；各自的“报名历史”显示对应状态。 |
| `REG-02` | 保持学生乙和活动 A，再点一次“提交报名”。 | 显示中文重复报名错误；学生乙的历史中仍只有一条活动 A 记录。 |
| `QRY-01` | 到“查询统计”→“活动报名名单”，选择活动 A、状态“全部”，点“查询”；再到“活动统计”选择活动 A、点“查询统计”。 | 名单两条，分别为正式报名和候补；统计显示容量 1、正式报名 1、候补 1、已取消 0、剩余名额 0、占用率 100.00%。 |
| `REG-03` | 回“报名与取消”，选择学生甲，在“报名历史”选中活动 A 的正式报名记录，点“取消选中报名”。再选择学生乙并刷新历史。 | 学生甲状态变为“已取消”；提示有候补递补，学生乙状态变为“正式报名”。历史仍保留学生甲的取消记录。 |
| `QRY-02` | 在“个人报名记录”分别选择学生甲、乙查询；在“活动报名名单”对活动 A 分别选“全部”“正式报名”“候补”“已取消”查询；重新查询活动统计。 | 甲为已取消，乙为正式报名；活动名单按四种筛选分别为 2、1、0、1 条；统计为正式 1、候补 0、已取消 1、剩余名额 0、占用率 100.00%。 |
| `QRY-03` | 在“总览统计”把“开始日期”改为活动 A 的活动开始日期，天数填 `1`，点“统计”。务必在创建活动 B 之前执行。 | 活动数量 1、正式报名 1、候补 0、已取消 1、去重参与学生数 1。 |
| `STU-03` | 回“学生管理”，选中学生乙，把姓名改为 `王五`，点击“保存姓名与年级”。再去“个人报名记录”查询学生乙。 | 学生列表与查询结果显示新姓名；学号、年级和报名状态未改变。 |
| `ACT-02` | 在“活动管理”选中活动 A，将名称改为 `校园阅读会`，点击“修改名称”。回“活动报名名单”查询该活动。 | 活动列表和查询中的名称同步更新；原有两条报名记录和状态不变。 |
| `ACT-03` | 按 `ACT-01` 的时间创建活动 B，选中活动 B，点击“关闭报名”；再尝试为学生甲报名活动 B。 | 活动 B 阶段显示“报名关闭”；新报名被拒绝。活动 A 的报名历史不受影响。 |
| `RESET-01` | 关闭程序并重新运行启动命令，分别查看学生、活动、报名及查询页签。 | 上一进程的学生、活动和报名记录均不存在；下拉列表为空。重新新增学生时编号从 1 开始。 |

**操作提醒：**报名页的“报名历史”跟随当前选中的学生；切换学生后先看表格是否已经刷新，必要时点击“刷新历史”。查询页切换后如选项未更新，点击外层“刷新”，并重新点击当前查询按钮。`RESET-01` 会清空本轮数据，请放在最后执行。

## 4. 异常与边界检查

建议在完成 `QRY-03` 后、执行 `RESET-01` 前检查。每次提交无效输入后，应确认有中文错误提示、原有列表和统计未被修改。下表只列出界面可直接复现的典型值。

| 编号 | 页面和输入 | 预期结果 |
| --- | --- | --- |
| `STU-E01` | 新增学生时学号填 `123` 或 `１２３４５６７８９０`。 | 拒绝；学号必须是 10 位 ASCII 数字。 |
| `STU-E02` | 姓名填 `张`；年级填 `0`、`5` 或 `2.5`。 | 拒绝；姓名为 2～20 字符，年级为 1～4 的整数。 |
| `STU-E03` | 未选中学生，点击“保存姓名与年级”。 | 提示先选择学生；列表不变。 |
| `ACT-E01` | 活动名称填 `课`；容量填 `0`、`101` 或 `1.5`；时长填 `29` 或 `241`。 | 拒绝；名称为 2～40 字符、容量 1～100、时长 30～240 分钟，整数项不能填小数。 |
| `ACT-E02` | 时间填 `2026/10/20 10:00`，或让报名截止早于报名开始，或让活动开始早于当前时间。 | 拒绝；时间必须为 `YYYY-MM-DD HH:MM:SS` 且顺序合法。 |
| `REG-E01` | 在报名页不选择学生或活动直接提交；在历史区不选择记录直接取消。 | 提示先选择对应对象；没有新报名或取消。 |
| `QRY-E01` | 个人或活动名单查询时，页码填 `0` 或 `10001`，每页填 `0` 或 `101`。 | 显示中文校验错误；有效范围分别为 1～10000 和 1～100。 |
| `QRY-E02` | 总览开始日期填 `2026/10/20`，或天数填 `0`、`366`。 | 显示中文校验错误；日期格式为 `YYYY-MM-DD`，天数为 1～365。 |

报名窗口刚好开关、活动开始后禁止取消、每名学生最多 3 条有效报名，以及并发报名容量控制等难以稳定手工卡点的情况，以固定时钟和并发自动化测试为准。可在 `tests/registrations/`、`tests/activities/` 与 `tests/integration/` 中查看对应测试。

## 5. 自动化检查

在仓库根目录另开 PowerShell，运行以下命令。若界面仍在运行，自动化测试使用独立的测试数据，不需要清空手工测试窗口。

```powershell
.venv\Scripts\python -m pytest -q
.venv\Scripts\python -m pytest -q tests/integration
.venv\Scripts\python -m pytest --cov=campusApp.core --cov-report=term-missing --cov-fail-under=80
```

记录每条命令的通过、失败和跳过数量，以及核心业务覆盖率。出现失败时保留完整错误堆栈和复现步骤；出现 Tk 相关跳过时记录运行环境，并按第 3 节完成手工界面验收。
